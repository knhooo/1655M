## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 하강(下降) 액션 아케이드 |
| 엔진 | Unity 6000.3.6f1, 2D URP |
| 언어 | C# (스크립팅 백엔드: Mono) |
| 플랫폼 | Windows x64 `.exe` |
| 신규 패키지 | Input System (그 외 표준 URP 2D 구성) |
| 물리 엔진 | **미사용** — Rigidbody/Collider 전무 |

**코어 루프:** 하강(채굴) → 전투 → 보상(재화·무기) → 아웃게임 장비 성장 → 재도전.
플레이어는 좌·우·아래·좌하·우하 5방향으로 한 칸씩 이동하며, 막힌 칸으로 이동을 시도하면 그 칸을 **자동 채굴/공격**한다(별도 공격 버튼 없음). 아래로 내려갈수록 지층이 단단해지고(흙→암반→광맥), 격자에 적·상자·재화·보스가 박혀 진로를 막는다.

## 2. 아키텍처

### 2.1 전체 구조

```
GameManager (씬 싱글톤, 상태 머신)
  Title ─▶ Inventory ─▶ Playing ─▶ Ending ─▶ (씬 리로드) ─▶ Title
    │
    ├─ MapGenerator ── 격자 지형 스트리밍 + 엔티티/보스/편대 배치
    │     └─ BlockView(풀) · GridEntity(프리팹별 풀): Enemy / Chest / CurrencyNode / Boss
    │
    ├─ PlayerController (씬 싱글톤) ── 그리드 스텝 이동·채굴·낙하·HP
    │     ├─ PlayerStats (static + PlayerPrefs) ── 강화·장착 검·치명타
    │     ├─ SkillSystem ── Skill 컴포넌트 자동 수집 (Dash/Shield/Shockwave)
    │     ├─ PlayerAnimation ── 몸 비주얼 통합 (피격 플래시·사망 스캐터+파티클·보호막 링·스킬 발동 이펙트)
    │     └─ PlayerWeapon ── 장착 무기 표시 + 부채꼴 스윙 + 슬래시 이펙트 (무기는 별도)
    │
    ├─ CameraFollow ── 하강 전용 추적 + 사망 되감기 + 흔들림
    │
    ├─ 이코노미: RunWallet(런) / RunInventory(런) ─(사망 시)▶ PlayerPrefs 영구 저장
    │
    ├─ 연출: JuiceDirector(히트스톱+흔들림, 사망 포함) · DamageNumbers · BossAttackVisual
    │        LowHealthVignette · PlayerAnimation(플레이어 몸)
    │
    ├─ 오디오: SfxPlayer(싱글톤) + SfxBank(SO) + SfxHub(이벤트 배선)
    │
    └─ UI: HudView · CurrencyDisplay · UpgradePanel · SwordPanel · BossHud · TitleScreen ...
           (전부 이벤트 구동 — 매 프레임 폴링 없음)
```

### 2.2 격자 맵 = 행 스트리밍 + 풀링

- `MapGenerator`가 추적 대상(플레이어)의 깊이를 기준으로 **아래 `_rowsAhead`행을 미리 생성**하고, 위로 벗어난 행은 회수한다.
- 블록 뷰는 `UnityEngine.Pool.ObjectPool<BlockView>`, 엔티티는 **프리팹 단위 풀**로 재사용한다.
- 행 데이터 객체(`MapRow` — 배열 3개 보유)도 `Stack<MapRow>` 풀로 재사용해 스트리밍 중 GC 할당을 억제한다.
- **지나온 지형 유지 옵션**(`_keepPassedTerrain`): 원작처럼 파낸 터널을 남긴다. 위로 벗어난 엔티티는 회수 대신 `SetFrozen(true)`(컴포넌트 비활성)로 **Update만 정지**하고 스프라이트는 유지. `_maxRowsBehind`를 넘어가면 완전 회수(메모리 안전장치).

### 2.3 칸 = 블록 OR 엔티티

- 각 칸은 지층 블록(`BlockData` 값 타입) **또는** `GridEntity`(적·상자·재화·보스) 중 하나.
- 엔티티가 점유한 칸은 solid 취급되고, `MapGenerator.DamageCell(col,row,amount)`이 엔티티가 있으면 엔티티로, 없으면 지층으로 피해를 라우팅한다.
- 2×2 이상 엔티티와 편대는 아직 생성되지 않은 아랫행 칸을 `_pendingEntityCells` 딕셔너리에 예약해 두고, 해당 행이 생성될 때 소비한다.

### 2.4 절차적 배치 = 결정론적 해시

- 지층 종류, 엔티티 스폰, 편대, 진입 통로 등은 모두 순수 함수 `Hash01(col, row, salt)`(정수 해시 → 0~1)로 결정한다.
- 저장이 필요 없고, 같은 시드면 같은 맵이 재현된다. 스트리밍/회수 반복에도 결과가 흔들리지 않는다.
- 지층은 노이즈가 아니라 **명시적 레이어**(`StrataLayer[]` {type, thickness})로 깊이 구간을 나눈다.

### 2.5 이동 = 그리드 스텝 (물리 없음)

- Rigidbody/Collider 없음. `transform.position`을 칸→칸으로 `LerpUnclamped` 보간.
- 중력 = 매 틱 "아래 칸이 solid인가" 검사 → 아니면 낙하 애니메이션.
- 이동/채굴/타격이 한 경로: 막힌 칸으로 이동 시도 → `PlayerStats.Damage`(치명타 롤 포함)로 그 칸을 때림.
- 적 접촉 피해, 스킬 범위, 보스 공격 판정은 전부 **맨해튼 거리 / 셀 좌표 비교**로 처리(브로드페이즈 비용 0).

### 2.6 스킬 = 컴포넌트 + 쿨다운

- `Skill` 추상 베이스가 쿨다운·발동 조건·`Activated` 이벤트를 공통 처리, 구체 스킬은 `OnActivate()`만 구현.
- `SkillSystem`이 같은 오브젝트의 `Skill` 컴포넌트들을 `Slot` 번호(0~2)로 **자동 수집**(드래그 불필요). 슬롯 = 단축키(Z/X/C) = 강화 항목.
- 배타적 이동(돌진)은 `PlayerController` 코루틴이 제어, 보호막은 타이머 버프, 충격파는 즉발 원형 판정.

### 2.7 이코노미 / 성장

- 재화 5종(Coin/Gold/Rune1~3). `CurrencyCost`는 enum 크기의 `int[]`를 감싼 `readonly struct`.
- 런 중 획득은 `RunWallet`(메모리), 사망 시 `BankToTotal()`로 `PlayerPrefs`(`total_currency_N`)에 적립.
- 무기는 "검" 한 종류 5등급(enum). 등급은 치명타 확률에만 영향(`((int)rarity+1) * 5%`). 상자에서 가중치로 드롭, 아웃게임 Sword 탭에서 수동 장착.
- 강화 항목: Damage / Armor(HP) / Skill1~3. 비용 선형(레벨당 +1), 항목별 소모 재화 조합이 다름.
- 저장 키: `best_depth`, `total_currency_N`, `upg_lv_N`, `owned_swords`, `equipped_sword`.

### 2.8 흐름 / 사망 시퀀스

- `GameManager` 상태 머신: `Title → Inventory → Playing → Ending`.
- 사망 → 스트리밍 정지 → 카메라가 지나온 길을 따라 시작 높이까지 되감아 올라감 → 결과(점수/최고 점수/획득 재화) 표시 → 페이드 → **같은 씬 리로드**(= 완전 리셋, 싱글톤 재생성).

### 2.9 적 / 보스

- 일반 적: 격자에 박힌 정지형. 인접 시 일정 간격 접촉 피해. 처치 시 코인 드롭 + **위로 튕겼다가 화면 밖으로 낙하 후 삭제**(`DeathToss`).
- 편대: 같은 적을 정해진 모양(가로 일자 / 속 빈 삼각형 / 상자를 감싼 3×3)으로 무리 배치.
- 보스: **9×9 격자 점유**(가로 전폭을 막음), 특정 깊이에 런당 1회 등장. 진입 직전 5행의 가운데 칸을 비워 낙하 통로를 만든다. 첫 피격 이후 공격 개시.
  - 공격 = 텔레그래프(경고 마커 깜빡임) → 딜레이 → 강타. 강타는 **플레이어만** 피해(지층·일반 적 안 건드림).
  - **보스 A**: 세로/가로 직선 강타. 이펙트는 라인 따라 원형 충격파가 연속으로 터짐(가로 왼→오, 세로 아래→위). 가로는 한 칸 걸러(oxox…) + 안전지대 랜덤.
  - **보스 B(`Boss2 : Boss`)**: 머리에서 대각선 위로 파이어볼(사각 범위 안 4벽 튕김, 플레이어에 닿아도 안 사라짐) + 토네이도(세로 라인 경고 → 거기 있으면 붕 떴다가 착지, 조작 불가).
  - **페이즈**: HP 절반 이하 → (A) 공격 간격·경고 시간 단축 + 가로 안전지대 축소 + 세로 3열화, (B) 파이어볼 양쪽 동시 + 토네이도 다수 라인.
  - 공격 패턴은 `ChooseAttack` / `BuildAttackCells` / `OnAttackStrike` 오버라이드로 서브클래스가 확장.
  - **보스 애니메이션**(`BossAnimation`): Animator 컨트롤러의 Idle / attack / die 상태를 상황별로 재생(파라미터 없이 CrossFade). 예고 시 attack, 경고 딜레이+여운 후 Idle 복귀, 사망 시 die. 사망 후 `Boss._deathAnimHold` 만큼 격자 회수를 지연해 die 재생 시간 확보. 피격 시 스프라이트 흰 플래시(선택).

- 아이템: `PickupEntity` 베이스(재화처럼 인접 시 자동 획득, 프리팹을 `_entityTable` 에 등록). 2종 —
  - **체력 회복**(`HealItem`): 고정량 또는 최대 HP 비율만큼 즉시 회복.
  - **ㄹ자 대시**(`DashItem`): 획득 즉시 방향열(`_pattern`, 기본 우3·아래1·좌3·아래1·우3)을 따라 연속 돌진하며 지층·적을 관통 타격. `PlayerController.StartPathDash` 로 구현.

### 2.10 연출(손맛)

- `JuiceDirector`가 `DamageDealt` / `DamageTaken` / `ShockwaveFired` 이벤트를 구독해 `HitStop`(Time.timeScale 순간 0) + `CameraFollow.Shake`(Perlin 노이즈 기반 감쇠 흔들림)로 라우팅.
- 플로팅 데미지 숫자(`DamageNumbers`) — 풀링된 3D TextMeshPro. 플레이어 피격=마젠타 상승, 적 피격=그린 포물선, 치명타=빨강.
- 파괴된 블록도 스프라이트를 복제해 튕겨 날림(`BlockView.PlayDestroyToss`) 후 자기 풀에 반납.
- 저체력 시 화면 빨강 비네트 맥동, HP 감소 시 HP 바 흰색 플래시.
- 보스 경고/강타 마커도 풀링(`BossAttackVisual`).

### 2.11 오디오

- `SfxPlayer` 싱글톤 — 다수 `AudioSource`를 라운드로빈으로 돌려 겹쳐 재생. 같은 사운드 연타는 최소 간격으로 무시(기관총 방지).
- `SfxBank`(ScriptableObject) — `SfxId` → 클립 배열(랜덤) + 볼륨 + 피치 흔들림.
- `SfxHub` — 씬 싱글톤 이벤트를 사운드로 배선(채굴·타격·치명타·피격·사망·재화·스킬). 적/상자/보스는 자체 코드에서 직접 호출.

### 2.12 배경

- 무한 스크롤: 카메라 추적 + 텍스처 UV 오프셋만 미는 방식(`ScrollingBackground`), 또는 스프라이트 2~3장 순환(`ScrollingBackgroundTiles`). 오브젝트 생성 없음.

## 3. 다수의 지층·적 처리 방식

| 기법 | 적용 |
|---|---|
| **행 스트리밍** | 플레이어 근처만 생성, 위로 벗어난 행 회수. 화면 밖 렌더는 URP 프러스텀 컬링이 처리 |
| **오브젝트 풀링** | 블록 뷰, 엔티티(프리팹별), 데미지 숫자, 보스 경고 마커, 파티클, `MapRow` 배열 |
| **물리 미사용** | 브로드페이즈/솔버 비용 0. 모든 판정이 셀 좌표·맨해튼 거리 |
| **결정론적 해시 배치** | 월드 상태 저장 불필요, 스트리밍 반복에 안정적, 무할당 생성 |
| **지나친 엔티티 동결** | 회수 대신 컴포넌트 비활성 → 다수가 남아도 Update 비용 없음 |
| **이벤트 구동 UI** | HUD·재화·HP·쿨다운을 이벤트로만 갱신(폴링 없음). UI 값은 바뀔 때만 대입해 Canvas 리빌드 억제 |
| **값 타입** | `BlockData`, `CurrencyCost`(int[] 래핑 readonly struct) |
| **스프라이트 아틀라스** | Kenney 스프라이트를 아틀라스로 묶어 SetPass calls **24 → 10 (약 58%↓)** |
| **빌드 정리** | 디버그 HUD(`OnGUI`) 등은 `#if UNITY_EDITOR`로 빌드에서 제외 |

## 4. 최적화 방식과 선택 이유

- **왜 물리 엔진을 안 썼나** — 게임이 완전한 격자 기반이고 이동이 이산적이다. Rigidbody는 연속 충돌·솔버 비용만 늘리고, 격자에서는 "칸이 solid인가" 한 번의 딕셔너리 조회로 충분하다. 적/블록이 화면에 수십 개 있어도 물리 오버헤드가 0이다.
- **왜 스트리밍 + 풀링인가** — 세로 무한 맵이므로 전부 인스턴스화하면 메모리·드로우콜이 깊이에 비례해 증가한다. 플레이어 근처만 유지하고 재사용하면 상수 비용에 수렴한다.
- **왜 결정론적 해시인가** — 맵을 저장하지 않아도 재현 가능하고, 스트리밍으로 같은 행을 다시 만들어도 동일 결과가 나온다. 생성 시 임시 배열 할당이 없다.
- **왜 이벤트 구동 UI인가** — HP·재화·쿨다운을 매 프레임 읽어 UI에 쓰면 값이 안 바뀌어도 Canvas가 dirty 된다. 이벤트로 바뀔 때만, 그리고 실제로 값이 달라졌을 때만 대입한다.
- **왜 지나친 엔티티를 지우지 않고 동결하나** — 원작처럼 파낸 흔적을 남기고 싶었고, 지나친 적이 화면에 보이는 편이 자연스럽다. 다만 그 적들이 계속 `Update`를 돌면 깊이에 비례해 비용이 늘므로 컴포넌트만 끈다.

## 5. AI 활용 범위와 방법 (필수 기재)

본 과제는 100% 본인이 설계·판단·검증하였으며, **Claude Code (Anthropic, claude-sonnet-5)** 를 보조 도구로 사용하였다. 활용 내역:

| 범위 | 방법 | 본인 수행 부분 |
|---|---|---|
| 일정 설계 | 마감 역산 타임라인 초안 작성 요청 | 우선순위·스코프 결정, 매일 재조정 지시 |
| 코드 스캐폴딩 | 시스템별 골격 코드 생성 요청 (맵 스트리밍, 플레이어 컨트롤러, 스킬 베이스, 이코노미, 보스, 연출, 오디오 등) | 요구사항 정의, 게임 규칙·수치 결정, 씬/프리팹 구성, 통합·배선 |
| 아키텍처 검토 | "싱글톤 vs 주입", "이벤트 패턴", "보스 패턴 확장성" 등 트레이드오프 논의 | 최종 채택 결정 |
| 디버깅 | 증상 설명 → 원인 후보·진단 로그·수정안 제시 | 재현, 로그 확인, 수정 검증, 채택 여부 판단 |
| 리팩토링 | 중복 제거·풀링 도입·구조 분리 제안 및 적용 | 범위 지정, 회귀 확인 |
| 문서 | 본 기술 명세서 초안 작성 | 사실 확인, 수정, 최종본 |

AI가 생성한 코드는 전부 본인이 읽고 프로젝트에 통합하며 동작을 검증하였다. 게임 디자인(코어 루프, 지층/스킬/보스 규칙, 밸런스 수치, UI 흐름)은 본인이 정의하고 지시하였다.
